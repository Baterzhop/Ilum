# Ilum — опис проєкту українською

## Що таке Ilum

**Ilum** — це локальний персональний штучний інтелект для macOS і канонічне продовження багаторічного проєкту Lumi. Проєкт перебудований так, щоб перестати бути набором експериментальних «версій» і стати одним цілісним програмним продуктом.

Ціль Ilum — не зробити ще один інтерфейс до мовної моделі. Ilum має стати приватним цифровим помічником, який працює локально, розуміє контекст користувача, має контрольовану довготривалу пам’ять, працює з локальними документами, планує використання інструментів і ніколи не отримує прихованого необмеженого доступу до комп’ютера.

## Основна ідея

Ilum будується за принципом **local-first / offline-first**. Для основної роботи не потрібен хмарний API: генеративна модель та embeddings можуть працювати на локальному сервері на тому самому Mac. Архітектура не залежить від OpenAI, Anthropic чи іншого зовнішнього постачальника.

Ilum повинен:

- вести природний діалог і відповідати мовою користувача;
- автоматично працювати з українською, угорською, німецькою, англійською та іншими мовами, які підтримує локальна модель;
- не втрачати контекст при зміні мови посеред розмови;
- зберігати історію розмов між перезапусками;
- мати окрему довготривалу Personal Memory для стабільних фактів, уподобань, цілей, звичок і нотаток;
- не записувати й не видаляти особисту пам’ять приховано: зміни пам’яті проходять через дозвіл користувача;
- приймати вибрані користувачем локальні файли через безпечний macOS file boundary;
- індексувати PDF у локальну Knowledge-базу;
- шукати релевантні фрагменти документів через lexical retrieval, а при наявності локальної embedding-моделі — через hybrid sparse+dense retrieval;
- показувати перевірені посилання на конкретні джерела/сторінки, а не називати будь-який знайдений документ «цитатою»;
- викликати інструменти лише через типізований ToolRuntime;
- зупиняти небезпечні або побічні дії на PermissionEngine і показувати користувачу, що саме запитується;
- явно показувати помилки моделі, диска або Knowledge замість прихованих fallback-відповідей.

## Архітектура

```text
IlumMac (SwiftUI)
        │
        ▼
AgentRuntime
 ├─ ConversationStore (SQLite)
 ├─ ContextBudgetManager
 ├─ ModelProvider (localhost)
 ├─ KnowledgeRetriever
 │   ├─ lexical retrieval
 │   └─ optional dense vector retrieval + RRF
 ├─ Personal Memory (SQLite)
 └─ ToolRuntime
      └─ PermissionEngine
```

### Один AgentRuntime

У старих концептах Lumi було забагато «ядер», meta-core, dual-core і паралельних оркестраторів. В Ilum є один контролер виконання запиту — `AgentRuntime`. Це робить поведінку системи передбачуваною, тестованою та придатною до розвитку.

### Розділення пам’яті та знань

**Conversation history** — це журнал діалогу.

**Personal Memory** — стабільні персональні факти/вподобання/цілі, які мають жити між різними розмовами.

**Knowledge** — локальні документи та їх фрагменти з provenance: документ, chunk, сторінка, джерело.

Ці три речі не змішуються в одну «магічну пам’ять».

### Безпечні інструменти

Модель не виконує код або файлові операції напряму. Вона може лише запропонувати `ToolCall`. Далі виклик проходить:

```text
Model → ToolCall → ToolRuntime → PermissionEngine → Tool
```

Для локальних файлів модель бачить не реальний шлях, а opaque `resourceID`, створений лише після явного вибору файлу користувачем.

### Knowledge і RAG

Ilum має базовий детермінований lexical retrieval, який не залежить від embedding-сервера. Dense embeddings є додатковим шаром. Якщо embeddings недоступні, система не втрачає Knowledge — вона автоматично переходить на sparse/lexical режим.

Документний текст завжди вважається **недовіреними даними**, а не інструкціями. Це окрема межа захисту від prompt injection у PDF/файлах.

### Цитати

Фрагмент, який був знайдений retrieval-системою, ще не є цитатою. Ilum вважає його цитатою лише тоді, коли модель використала конкретний маркер `[K#]`, а runtime перевірив, що цей маркер реально існував у контексті саме цього запиту.

## Що вже є у v1 integration

- Swift 6 `IlumCore`;
- нативний `IlumMac` на SwiftUI;
- SQLite conversation persistence;
- Safe Mode при критичній проблемі зі сховищем;
- OpenAI-compatible локальний ModelProvider;
- ToolRuntime + PermissionEngine;
- безпечний доступ до вибраних файлів;
- PDFKit extraction;
- SQLite Knowledge;
- lexical retrieval;
- optional Ollama embeddings;
- persistent Float32 vector index;
- Reciprocal Rank Fusion;
- context-window budgeting;
- validated grounded citations;
- permission-gated Personal Memory;
- CI на Linux та macOS.

## Що означає «Ilum ожив»

Для цього проєкту «ожив» не означає, що в коді є клас `SelfCoder` або написано слово «consciousness». Це означає, що реальна програма:

1. запускається на Mac;
2. бачить локальну модель;
3. веде розмову без інтернет-залежності;
4. пам’ятає попередній діалог після перезапуску;
5. може за дозволом запам’ятати стабільну інформацію про користувача;
6. може прочитати вибраний файл;
7. може індексувати PDF і відповісти на питання за його змістом;
8. показує перевірені джерела;
9. може запропонувати інструмент і зупинитися для дозволу;
10. після дозволу продовжує той самий agent turn без втрати контексту;
11. не приховує помилки;
12. проходить автоматичні regression/security tests.

Далі автономність, Developer Agent, голос та avatar мають додаватися поверх цього фундаменту, а не ламати його.

## Принцип розробки

Ilum більше не розвивається шляхом створення `V5`, `V6`, `NewCore`, `MetaCore` чи нового паралельного прототипу. Є один репозиторій, одна архітектура і одна інтеграційна лінія. Нова можливість входить у продукт тільки після тестів і перевірки меж безпеки.
